# AI Analyst Lab 게시 원칙

## 승인된 운영
- 사용자 선택은 GitHub Pages이며 Notion은 추가 수정하지 않는다.
- 2026-10-03~2026-10-07 한국시간 18:00에 매일 실기업 보고서 2개를 작성·게시한다. 이후 연장하지 않는다.
- Codex 대화 heartbeat ai-analyst-lab-github가 실행을 맡는다. GitHub Pages는 main 변경을 배포한다. 저장소 자체에 AI 분석 예약 실행기가 있는 것은 아니다.
- 기존 ChatGPT 예약은 별개이며 취소·변경되지 않았다.
- 2026-10-03 SK하이닉스 선공개분은 당일 정규 2개에서 제외한다.

## 품질
실제 공시·IR 우선. 최근 회사 공지 확인. 사실/회사 전망/자체 추정/미확인을 구분. 출처 링크·발표일·열람일·연결/별도·단위 명시. 미확인 시세/컨센서스/배수 근거를 만들지 않는다. 주가 판단 보류가 근거 없는 목표가보다 낫다. 예측모델 산식과 자체 가정을 공개한다. 과거 순이익을 연간화하기 전 비영업 항목과 세효과를 검토한다. 재게시본으로 본 원문을 직접 대조 완료라고 표현하지 않는다. 사람 미검토 상태를 표시하고 투자권고로 표현하지 않는다. 가상 샘플을 실제 분석으로 취급하지 않는다.

## 파일 구조
- assets/site.css: 공통 스타일
- reports/YYYY-MM-DD-company.html: 상세 보고서. 상대 경로 ../assets/site.css 사용
- 같은 이름 .md: 전체 분석 원문
- 같은 이름 .json: 수치, 가정, 출처, 확인 한계
- reports/index.json: 보고서 메타데이터 배열. 고유 id, date, company, html, publicationType 필수
- index.html: 최신 보고서 목록. 새 보고서를 추가하고 개수·최신일 업데이트
- samples/: 기존 디자인 샘플 보관

## 게시 절차
원격 main 최신 상태 읽기 → 동일 id·날짜 중복 확인 → 자료 확인 → 분석 및 산식 점검 → HTML/MD/JSON 동일성 확인 → 파일 링크 확인 → 기존 파일을 보존하는 원자적 커밋 → force 없이 main 업데이트 → 해당 커밋의 Pages 배포 성공 확인. 충돌하면 다시 읽고 병합한다. 실패 시 성공으로 알리지 않는다. 보고서가 1개만 근거를 충족하면 부족한 1개를 만들어내지 말고 부분 완료와 사유를 보고한다.

## 알림
실제 게시 성공 시 링크와 핵심 관찰을 알린다. 실패·권한 만료·자료 검증 문제는 구체적으로 알린다. 첫 예약 실행 이전에 전체 무인 운영 검증을 마쳤다고 말하지 않는다.
